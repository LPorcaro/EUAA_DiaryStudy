# Analysis pipeline

This repository contains the analysis pipeline for a
two-week diary study (N=9) on how listeners notice, interpret, and respond
to problematic recommender-system behaviours (PBs) on music streaming
platforms. It supports a manuscript targeting *ACM Transactions on
Computer-Human Interaction* (TOCHI).

Three PB macro-categories structure the analysis:

| Code | Construct |
|------|-----------|
| SB   | Societal Bias |
| CI   | Commercial Imperatives |
| LD   | Limited Discovery |
| O    | Other / unclassified |

## What the pipeline does

Two scripts run in sequence:

1. **`src/analyze_events.py`** — event-level analysis. Loads the raw diary
   entries, maps free-text PB selections to the SB/CI/LD/O taxonomy,
   checks scale reliability (Cronbach's α), computes conditional
   probabilities P(PB | context) with permutation tests and BH-FDR
   correction, and correlates PB triggers with the three Likert appraisal
   items (ALGO_CAUSE, FUTURE_USE, ARTIST_HARM). Exports an enriched
   event-level CSV consumed by the next script.
2. **`src/analyze_participants.py`** — participant-level analysis. Loads
   the enriched CSV, aggregates to one row per participant, runs PCA +
   Ward hierarchical clustering, and reports Kruskal-Wallis comparisons
   across clusters (exploratory only, given N=9).

Both scripts print their statistical results to the console as they run
and also write every table and figure to disk (see **Outputs** below).

## Setup

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Requires Python 3.10–3.12.

### Font (optional)

Figures use Linux Libertine to match the paper's ACM `acmsmall` template.
If it isn't installed, the scripts fall back to matplotlib's default font
automatically (with a one-line warning) — the figures still render
correctly, just with a different typeface. To match the paper exactly:

```bash
# Debian/Ubuntu
sudo apt install fonts-linuxlibertine

# macOS (Homebrew)
brew install --cask font-linux-libertine
```

If your Libertine install lives somewhere other than
`/usr/share/fonts/opentype/linux-libertine/`, add that path to
`_LIBERTINE_CANDIDATES` in `src/config.py`.

## Running

From the `EUAA_DiaryStudy/` directory:

```bash
cd src
python3 analyze_events.py        # step 1: event-level analysis
python3 analyze_participants.py  # step 2: participant-level analysis (reads step 1's output)
```

Run them in that order — `analyze_participants.py` reads the enriched CSV
that `analyze_events.py` produces and will raise a clear error if it can't
find it.

Both `main()` functions accept path/parameter overrides, e.g.:

```python
from analyze_participants import main
main(k=3)  # force 3 clusters instead of auto-selecting via silhouette score
```

## Outputs

**`outputs/tables/`**

| File | Produced by | Contents |
|------|-------------|----------|
| `events_enriched.csv` | analyze_events.py | Original diary events + binary PB trigger columns |
| `construct_probs_{INTENT,TEMP,TRIGGERS}.csv` | analyze_events.py | Construct-level P(PB \| context) |
| `conditional_probs_{INTENT,TEMP,TRIGGERS}.csv` | analyze_events.py | Item-level P(PB \| context), CIs, effect sizes, FDR-corrected p-values |
| `likert_pb_correlations.csv` | analyze_events.py | Participant-level Spearman ρ between Likert items and PB triggers |
| `participant_summary.csv` | analyze_participants.py | One row per participant: PB rates/counts, context proportions, Likert means, cluster assignment |
| `cluster_profiles.csv` | analyze_participants.py | One row per cluster with aggregated features |
| `pca_loadings.csv` | analyze_participants.py | Feature loadings per retained principal component |

**`outputs/figures/events/`** and **`outputs/figures/participants/`**

All figures are saved as 300 dpi PNGs, numbered in pipeline order (e.g.
`fig01_trigger_temp_intent.png`, `fig12_pca_biplot.png`).

## Notes on the statistics

- **N=9.** All clustering and cross-cluster comparisons in
  `analyze_participants.py` are exploratory and hypothesis-generating; no
  claims about generalisability or cluster stability are warranted at
  this sample size.
- **Reproducibility.** All permutation tests use a fixed seed (`seed=42`
  by default), so re-running the scripts on the same input reproduces the
  same p-values and effect sizes exactly.
- **Measurement model.** SB4 was reclassified to CI5 on empirical and
  conceptual grounds during scale development; `analyze_events.py` reports
  reliability statistics for both the original and revised item sets.
- **Performance.** The permutation tests in `analyze_events.py` are the
  slowest part of the pipeline (10,000 permutations × 13 PB triggers × 3
  context variables, plus × 3 Likert items for the correlation tests).
  The context-variable tests are vectorised; the Likert–PB correlation
  test deliberately still calls `numpy.corrcoef` once per permutation
  rather than a faster hand-rolled formula, because the two are not
  bit-identical in floating point and the difference shifts some
  permutation p-values in the fourth decimal place. A full run of both
  scripts takes roughly 30 seconds on a laptop.
