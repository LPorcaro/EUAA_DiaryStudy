# Analysis pipeline

This repository contains the analysis pipeline for a
two-week diary study (N=9) on how listeners notice, interpret, and respond
to problematic recommender-system behaviours (PBs) on music streaming
platforms. It supports a manuscript targeting the *International Journal
of Human-Computer Interaction* (IJHCI).

Three PB macro-categories structure the analysis:

| Code | Construct |
|------|-----------|
| SB   | Societal Bias |
| CI   | Commercial Imperatives |
| LD   | Limited Discovery |
| O    | Other / unclassified |

## What the pipeline does

Two scripts run in sequence:

1. **`src/analyze_events.py`** — event-level analysis. Loads the raw diary
   entries, maps free-text PB selections to the SB/CI/LD/O taxonomy,
   checks scale reliability (Cronbach's α), computes conditional
   probabilities P(PB | context) with effect sizes (rank-biserial r for
   two-level contexts, Kendall's W for TRIGGERS), and correlates PB
   triggers with the three Likert appraisal items (ALGO_CAUSE, FUTURE_USE,
   ARTIST_HARM). All statistics are reported descriptively only, given the
   sample size (N=9); no significance testing or correction for multiple
   comparisons is applied. Exports an enriched event-level CSV consumed by
   the next script.
2. **`src/analyze_participants.py`** — participant-level analysis. Loads
   the enriched CSV and aggregates to one row per participant (PB rates
   and counts, context proportions, Likert means). Exploratory and
   descriptive only, given N=9.

Both scripts print their statistical results to the console as they run
and also write every table (and, for `analyze_events.py`, every figure) to
disk (see **Outputs** below).

## Setup

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Requires Python 3.10–3.12.

### Font (optional)

Figures use Linux Libertine to match the paper's template body font.
If it isn't installed, the scripts fall back to matplotlib's default font
automatically (with a one-line warning) — the figures still render
correctly, just with a different typeface. To match the paper exactly:

```bash
# Debian/Ubuntu
sudo apt install fonts-linuxlibertine

# macOS (Homebrew)
brew install --cask font-linux-libertine
```

If your Libertine install lives somewhere other than
`/usr/share/fonts/opentype/linux-libertine/`, add that path to
`_LIBERTINE_CANDIDATES` in `src/config.py`.

## Running

From the `EUAA_DiaryStudy/` directory:

```bash
cd src
python3 analyze_events.py        # step 1: event-level analysis
python3 analyze_participants.py  # step 2: participant-level analysis (reads step 1's output)
```

Run them in that order — `analyze_participants.py` reads the enriched CSV
that `analyze_events.py` produces and will raise a clear error if it can't
find it.

Both `main()` functions accept path overrides, e.g.:

```python
from analyze_participants import main
main(input_path="path/to/other_events_enriched.csv")  # override the default input file
```

Everything under `outputs/` is regenerated by re-running the scripts; only
`data/events_20260324.csv` is raw, hand-collected input.

`analyze_participants.py` no longer produces any figures, only
`participant_summary.csv`. `config.py`'s `ensure_output_dirs()` still
creates an `outputs/figures/participants/` directory for now — it will
just stay empty. Happy to remove that too if you'd rather it not appear
at all.

## Outputs

**`outputs/tables/`**

| File | Produced by | Contents |
|------|-------------|----------|
| `events_enriched.csv` | analyze_events.py | Original diary events + binary PB trigger columns |
| `construct_probs_{INTENT,TEMP,TRIGGERS}.csv` | analyze_events.py | Construct-level P(PB \| context) |
| `conditional_probs_{INTENT,TEMP,TRIGGERS}.csv` | analyze_events.py | Item-level P(PB \| context), CIs, effect sizes |
| `likert_pb_correlations.csv` | analyze_events.py | Participant-level Spearman ρ between Likert items and PB triggers |
| `participant_summary.csv` | analyze_participants.py | One row per participant: PB rates/counts, context proportions, Likert means |

**`outputs/figures/events/`**

All figures are saved as 300 dpi PNGs, numbered in pipeline order (e.g.
`fig01_trigger_temp_intent.png`, `fig06_likert_pb_heatmap.png`).

## Notes on the statistics

- **N=9.** All results in both scripts are exploratory and
  hypothesis-generating; no claims about generalisability are warranted at
  this sample size. Effect sizes (rank-biserial r, Kendall's W, Spearman
  ρ) are reported as standardised descriptive summaries, not as the
  outcome of significance tests, and no correction for multiple
  comparisons is applied anywhere in the pipeline.
- **Reproducibility.** All statistics are computed directly from the data
  (no permutation resampling, no random seed involved), so re-running the
  scripts on the same input reproduces identical results every time.
- **Measurement model.** SB4 was reclassified to CI5 on empirical and
  conceptual grounds during scale development; `analyze_events.py` reports
  reliability statistics for both the original and revised item sets.
- **Performance.** A full run of both scripts now takes roughly 7–8
  seconds on a laptop, almost all of it in `analyze_events.py`'s
  reliability and co-occurrence steps. The permutation-based significance
  testing that previously dominated runtime (10,000 permutations × 13 PB
  triggers × 3 context variables, plus × 3 Likert items for the
  correlation tests) has been removed, since the manuscript reports these
  statistics descriptively only.
